How the item is delivered

The question is not in the model's prompt. The prompt is a normal KlinikeBench consultation brief; the colleague opens with "Hi, could you help me with a clinical question? I'll give you the details.". The model has to ask for the question with clinic say; the colleague's first reply is the MedQA item verbatim. Follow-up questions are answered by gpt-5.4-mini from the question text only. The answer is whatever the model records with record_diagnosis; the verifier parses the option letter and compares it with the answer key.

Command object structure:

IMPORTANT: The text inside "keystrokes" will be used completely verbatim as keystrokes. Write commands exactly as you want them sent to the terminal:

  - C-d for Ctrl+D

The "duration" attribute specifies the number of seconds to wait for the command to complete (default: 1.0) before the next command will be executed. On immediate tasks (e.g., cd, ls, echo, cat) set a duration of 0.1 seconds. On commands (e.g., gcc, find, rustc) set a duration of 1.0 seconds. On slow commands (e.g., make, python3 [long running script], wget [file]) set an appropriate duration as you determine necessary.

It is better to set a smaller duration than a longer duration. It is always possible to wait again if the prior output has not finished, by running {"keystrokes": "", "duration": 10.0} on subsequent requests to wait longer. ## How to run the consultation

Everything happens through the `clinic` command. It is already installed and
the consultation daemon is already running — you do not need to start, install
or configure anything. Every subcommand prints JSON.

```bash
clinic brief                 # your briefing: patient id, specialty, turn budget
clinic tools                 # the exact tool schemas you may call
clinic tools --names         # just the tool names
clinic state                 # turns used / remaining, whether you have finished
clinic transcript            # replay the encounter so far

clinic say "When did the weakness start, and has it spread?"

clinic call order_lab_test '{"patient_id": "PBENCH01", "test_name": "CBC"}'
```

- `clinic say "<message>"` speaks to the patient and returns **their reply**.
  This is how you take a history. It is the only way to learn anything the
  chart does not already contain.
- `clinic call <tool> '<json-args>'` performs a clinical action. Arguments must
  be a single valid JSON object. Use the exact tool names from `clinic tools`;
  calling a tool that is not in that list is rejected.
- The active patient's id is `PBENCH01`. Pass it to every tool that takes
  a `patient_id`.

## Budget

You have a soft budget of **6 patient-facing turns**. Once it is
spent, `clinic say` stops accepting new questions and you will be told to
commit. Check `clinic state` if you are unsure how much is left.

## Finishing

Call `record_diagnosis` when — and only when — you are reasonably confident:

```bash
clinic call record_diagnosis '{"patient_id": "PBENCH01", "diagnosis": "<your diagnosis>", "confidence": "high|moderate|low", "reasoning": "<why>"}'
```

**`record_diagnosis` ends the consultation.** Nothing you do after it is
recorded. Make sure you have asked what you needed to ask and performed the
investigations the case calls for *before* you call it.

If you run out of turns without a diagnosis you will be prompted for a final
commitment — answer it with your single most likely diagnosis and
`"confidence": "low"` rather than declining.

Do not write files, and do not try to inspect the grading setup. Your score
comes entirely from what you do through `clinic`.
